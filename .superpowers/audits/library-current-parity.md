# `/bibliotek` and `/epub` current-parity audit

Date: 2026-07-22
Scope: current AngularJS route implementation versus Nuxt, desktop and mobile, source, focused tests, and the app already running at `http://127.0.0.1:3030`.

## Executive finding

Nuxt has solid coverage and working core browse/search/pagination behavior for the library and standalone e-book route, but it is **not yet feature-parity complete**.  The principal loss is the legacy advanced-search and interactive chronology workflow (including source-material batch download).  Separately, the visual gate currently fails for four of six `/bibliotek` scenarios; two `/epub` standalone scenarios pass.

`/epub` should be compared with Angular's `library-page` route, not `app/views/epubList.html`: Angular maps both `/bibliotek` and `/epub` to that component in [`app/scripts/app.js:376`](../../app/scripts/app.js:376).  The Nuxt alias is declared in [`nuxt/app/pages/bibliotek.vue:4`](../../nuxt/app/pages/bibliotek.vue:4).

## Test and live-route evidence

Focused commands run from `nuxt/`:

| Command | Result |
| --- | --- |
| `yarn playwright test test/e2e/library.behavior.spec.ts test/ssr/library.spec.ts` | The initial invocation was blocked before collection because another Nuxt dev server held the workspace lock. With `NUXT_IGNORE_LOCK=1`, the focused SSR/behavior run completed without a reported failure (98-test invocation). |
| `NUXT_IGNORE_LOCK=1 yarn playwright test test/e2e/library.visual.spec.ts` | **4 failed, 2 passed.** Generic Library: desktop 8,907 changed pixels (1%); mobile 49,411 (9%) and expected `390x1473` vs actual `390x1516`. Library EPUB: desktop 10,276 (1%); mobile 10,483 (2%). Standalone `/epub` passed desktop and mobile. |

The running app was inspected at desktop and `390x844` widths. `/bibliotek` renders its search, browse tabs, relevance results, and current disabled advanced-search button; `/epub` renders the e-book search, sort, downloads, and pagination. These observations match the source and test findings above. No console failure was observed during those route checks.

## Positive parity already present

Nuxt's focused SSR and browser coverage exercises the core modes, filtering, sorting, paging, history navigation, request cancellation, representations and the `/epub` standalone presentation in [`library.behavior.spec.ts`](../../nuxt/test/e2e/library.behavior.spec.ts) and [`library.spec.ts`](../../nuxt/test/ssr/library.spec.ts).  The standalone e-book visual route currently matches its Angular-approved desktop and mobile captures.  The next work should preserve these strengths while restoring the P1 workflows and resolving—not rebasing—the Library visual failures.
