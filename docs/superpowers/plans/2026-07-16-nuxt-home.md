# Nuxt Home page implementation plan

**Design:** `docs/superpowers/specs/2026-07-16-nuxt-home-design.md`

## Global constraints

- Preserve Angular visual/editorial authority exactly; do not redesign the page.
- Keep `/red/om/start/startsida-ny.html` as the live source.
- Keep page-only fetch/parser state in `index.vue`; do not add a composable.
- Do not add a FastAPI endpoint, generated-client shape, Angular bridge, or destination-route migration.
- Follow TDD, commit each task separately, and independently review every task.

### Task 1: Add deterministic Home content fixtures

**Frontend files:**
- Add test-only raw Home HTML/CSS/image fixtures
- Modify `nuxt/test/fixtures/v2-server.mjs`
- Modify fixture-server unit tests

1. Add a frozen representative fragment containing the exact stylesheet/background declarations and editorial markers/links.
2. Add failing fixture-server tests for the fixed Home content path, request ledger/reset, failure control, CSS, and image responses.
3. Implement the minimum deterministic fixture behavior without changing existing ledgers or production sources.
4. Run focused and complete Nuxt unit tests.
5. Commit `test(nuxt): fixture Home editorial content`.

### Task 2: Port the SSR Home page

**Frontend files:**
- Create `nuxt/app/pages/index.vue`
- Add/modify SSR and browser behavior tests

1. Add failing SSR tests for exact metadata, body class, headings, editorial markers/hrefs, extracted stylesheet/background, absent Angular control tags, one content request, and graceful upstream failure.
2. Add failing browser tests for no duplicate hydration fetch and Home-to-404-to-Home head/background/body cleanup and restoration.
3. Implement page-local `useAsyncData`, the narrow typed declaration parser, `/red/` path validation, stable serialized cache buster, `useSeoMeta`, and `useHead`.
4. Keep the exact legacy shell and render only the remaining trusted body with `v-html`.
5. Run focused SSR/e2e plus full unit, typecheck, build, and API freshness gates.
6. Commit `feat(nuxt): port Home page`.

### Task 3: Lock Angular visual parity

**Frontend files:**
- Add Angular Home authority capture
- Add Nuxt Home visual comparison
- Add desktop/mobile Home baselines

1. Route all Angular and Nuxt Home content/CSS/image requests to local fixtures and assert no production request escapes.
2. Capture desktop and mobile full-page authority images only after fonts, editorial content, runtime stylesheet, and background image are ready.
3. Inspect headings, runtime cards/content, shell corridors, background crop/color, typography, spacing, and responsive behavior.
4. Compare Nuxt at the existing near-pixel thresholds and fix only demonstrated migration drift.
5. Run complete Nuxt, unchanged Angular, visual, API freshness, typecheck/build, scope, and diff gates.
6. Commit `test(nuxt): lock Home parity`.

## Final review gate

- Compare the complete frontend range with the design.
- Verify `/red` is still the runtime editorial source and its control tags never reach rendered body HTML.
- Verify Home creates no FastAPI/client/composable or library/reader coupling.
- Verify route transitions leave no Home-only head, body, or background state behind.
- Fix every Critical/Important finding and rerun the clean whole-slice gates.
